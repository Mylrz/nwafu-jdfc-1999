# 西农机电足球队数字档案

西北农林科技大学机械与电子工程学院足球队宣传与纪念网站。球队创办于 1999 年，网站记录七冠影像、历届球员、逐年球衣号码、老队员留言与队史资料。

线上地址：<https://nwafu-jdfc-1999.mylrz.chatgpt.site/>

## 主要能力

- 七冠档案、9 张本轮新增真实影像与可暂停/全屏浏览的自动图库墙
- 2022—2026 七个冠军赛季独立分享主页，配套 canonical、Open Graph 与 sitemap
- “球队近况”持续更新区自动读取最新公开赛季与影像，不用虚构赛程或招新倒计时
- 赛季数据概览、姓名/号码/位置搜索
- 球员详情与逐年球衣号码时间线
- 球员本人创建或定向修改档案，管理员审核后公开
- 战袍资料征集、老队员留言、老照片与 PDF 投稿
- 投稿照片经授权确认后可直接发布到公共影像档案，并按赛季、队别检索
- 男子五人制、男子十一人制、女子五人制可分别维护独立赛季档案
- 管理员待办工作台、新旧资料差异审核与逐条防重复提交
- 球员手动维护、CSV 批量导入/导出、JSON 数据备份
- 多管理员并发编辑保护、软归档与失败分区重试
- 投稿图片在浏览器端压缩，降低手机流量与对象存储成本
- 手机端完整导航、安全区、横向赛季切换和减少动态偏好均已适配
- 公开表单按来源限频；上传文件校验真实格式，PDF 强制下载且媒体响应禁止 MIME 嗅探

## 技术栈

- React 19、Next.js 16、Vinext、Motion
- Cloudflare D1（结构化档案）与 R2（照片和 PDF）
- Drizzle ORM / Drizzle Kit
- Papa Parse（CSV）与 Compressor.js（图片预压缩）
- Sites 托管与 ChatGPT 身份认证

## 本地开发

要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

常用验证命令：

```bash
npm run build
npm run lint
npm test
```

## 数据迁移

修改 `db/schema.ts` 后先生成并检查迁移：

```bash
npm run db:generate
```

迁移文件位于 `drizzle/`，部署时由 Sites 数据库迁移流程应用。不要手工修改生产数据库绕过迁移。

## 管理员授权

网站不会再把第一位访问后台的用户自动设为管理员。管理员必须预先存在于 D1 的 `admins` 表，字段包括 ChatGPT `user_id`、邮箱和显示名称。新增管理员属于高权限操作，应由当前维护者在确认身份后完成。

后台入口：`/admin`

## CSV 导入规则

- 一行表示一名球员在一个赛季的记录。
- 同一球员可用多行记录不同赛季号码。
- 更新已有球员时优先填写后台导出文件中的“档案ID”。
- 不填写 ID 时，仅在“姓名 + 年级”唯一匹配时合并；存在歧义会拒绝写入。
- 单次最多 500 行、2 MB；浏览器预览通过后，服务端还会再次校验。

## 备份与隐私

后台可下载 JSON 数据备份，包含 D1 表与 R2 媒体清单。该 JSON 不包含照片/PDF 二进制文件；完整灾备还需要单独复制清单中的 R2 对象。

球员联系方式、资料投稿联系方式及管理员身份属于非公开数据，备份文件不得公开上传或转发。

## 影像发布流程

图片投稿不会自动公开。管理员在“档案发布”中填写赛季、队别、照片说明、署名与资料来源，并确认投稿者拥有公开授权后，才能发布到前台公共影像档案。HEIC 可以作为内部草稿保存，但公开前需转换为 JPG、PNG 或 WebP；PDF 始终作为内部资料，不进入图片画廊。

当前队别标识为：`men-futsal`、`men-11`、`women-futsal`、`mixed`、`other`。同一年度的不同赛制应分别建立赛季档案，避免男女足或五人制、十一人制资料混档。

留言、球员资料和档案投稿均有每日提交上限。限频只保存来源地址的 SHA-256 摘要，不保存明文 IP。

## 内容维护原则

- 不编造比赛比分、历史阵容、球衣设计或未确认荣誉。
- 2025 男、女子五人制冠军合并为一组影像，并使用 2025 男子五人制冠军图作为纪念封面。
- 球衣号码按赛季存储；球员换新球衣时新增当年记录，不覆盖往年号码。
- 常规下线使用“归档”并支持恢复；只有管理员输入当前球员姓名再次确认后，才允许执行不可逆永久删除。
